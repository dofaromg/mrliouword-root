# MRL 商業化策略（Commercialization）v0.1

> 定位文件：把 MRL 從個人系統推向正式商業營運的路線圖與決策依據。
> 涉及法律與稅務的段落為方向建議，執行前應諮詢會計師與律師。

## 1. 商業模式：建議路徑

MRL 的資產是「定義層 + 執行層 + 平台」，對應三種可疊加的變現模式：

| 模式 | 形式 | 收費 | 優先序 |
|------|------|------|--------|
| **A. API 訂閱** | `mrliouhan.ai` 對外開放 API（金鑰制） | 月費方案 + 用量計費 | **第一優先** |
| B. SaaS 產品 | `mrliouword.com` 上的終端產品 | Free / Pro 月費 | 第二 |
| C. 授權/白牌 | MRL 定義系統授權給企業內部使用 | 年度授權費 + 導入服務 | 有商機再做 |

**建議先做 A**：API 是你現有架構（Workers gateway）最短路徑的變現，
不需要打磨消費級 UI；B 靠 A 的基礎疊上去；C 是高單價但長銷售週期，被動等詢問即可。

## 2. 定價框架（初版假設，上線後迭代）

```text
Free      NT$0        低額度 API 呼叫、社群支援 —— 目的是讓人試用
Pro       月費制      固定額度 + 超量計費、Email 支援（SLA 目標 99.5%）
Enterprise 年約議價   專屬額度、SLA 保證、DPA、發票/合約 —— 洽 legal@
```

原則：
- 免費層要「夠試用、不夠營運」，額度是唯一的閘門。
- 計費單位選一個你能在 gateway 準確計量的東西（呼叫數或 token 數），
  從第一天就把用量記錄進資料層（D1/KV），否則之後無法回溯收費。
- 定價寫在網站上公開，Enterprise 除外。

## 3. 法律主體與稅務（台灣）

| 階段 | 建議 | 理由 |
|------|------|------|
| 月銷售額未達起徵點 | 可暫以個人名義 | 自 2025 年起,網路銷售**勞務**營業稅起徵點為**每月 NT$50,000**（銷售貨物為 NT$100,000）。未達起徵點得暫免辦「稅籍登記」,但**仍須將營利所得併入綜合所得申報** |
| 開始穩定收費 | **設立有限公司** | 責任隔離（AI 服務有輸出風險）、開發票、金流申請、B2B 簽約都需要 |
| 有國際收入 | 公司 + 外幣帳戶 | Stripe 等國際金流需正式主體 |

> **重要區辨**:「稅籍登記」(國稅局,與營業稅有關) 與「公司／商業登記」(經濟部/商業司,與法人資格有關) 是**不同義務**,不可混為一談。
> 實際的稅籍登記、發票、營業稅、所得稅義務**取決於實際營業型態**,上表僅為方向,**務必由會計師依最新法規核實**。

要點：
- AI 服務的責任風險（輸出錯誤、資料外洩）是設公司而非行號的核心理由——
  有限公司把風險隔離在公司資本內。
- 統一發票、勞健保、營所稅請直接找會計師事務所包月記帳（月費約 NT$2,000–3,500）。
- 網域、Cloudflare 帳號、商標之後都應**移轉到公司名下**，
  對應 SOVEREIGNTY.md 時把「Root Owner」定義為公司 + 你個人的雙層結構。

## 4. 商標與智財

### 4.1 商標（優先辦，先申請先贏）

- 申請標的：**「MRL」與「MrLiouWord」文字商標**（先文字，Logo 定稿後再補圖形）。
- 台灣（TIPO）：類別建議 **第 9 類**（軟體）、**第 42 類**（SaaS/軟體服務）；
  規費每類 NT$3,000，可自行線上申請或委託事務所（每件約 NT$8,000–15,000）。
- 國際：有海外收入後再透過**馬德里體系**指定美/日/歐，以台灣註冊為基礎。
- 注意：「MRL」三字母商標在第 9 類可能有近似案，申請前先在
  TIPO 檢索系統查近似商標；若有衝突，主推「MrLiouWord」。

### 4.2 程式碼保護

- 本倉庫已改為**專有授權**（見 LICENSE.md）。
- **建議**：治理與文件（本倉庫）可維持公開展示；
  真正的商業核心（gateway 邏輯、定義引擎、計費）應放**私有倉庫**。
  公開倉庫裡的東西，license 再嚴格，實務上都應視為「別人看得到」。

## 5. 金流

| 情境 | 方案 | 備註 |
|------|------|------|
| 台灣客戶、快速上線 | 綠界/藍新/TapPay | 需公司或行號，串接發票 |
| 國際客戶、最省事 | **Paddle 或 Lemon Squeezy（MoR）** | 商家記錄模式，代處理全球稅務與請款，抽成較高（~5%+），但一人公司最務實 |
| 國際客戶、規模化後 | Stripe | 費率較低，但稅務申報自理 |

**建議起步用 MoR（Paddle/Lemon Squeezy）**：一人營運不該把時間花在各國稅務。

## 6. B2B 銷售必備文件（依需求順序準備）

1. ✅ 服務條款、隱私政策（草案已在 `docs/legal/`）
2. ✅ SLA 草案（`docs/business/MRL_SLA.md`）
3. DPA（資料處理協議）—— 第一個 B2B 客戶要求時再請律師出
4. 資安說明文件（架構圖、加密、備份政策——`MRL_OPERATIONS.md` 已可改寫成對外版）
5. SOC 2 / ISO 27001 —— 遠期，有大企業客戶明確要求再投入

## 7. 依賴風險（誠實面對）

| 風險 | 影響 | 緩解 |
|------|------|------|
| 上游 AI API（Anthropic/OpenAI）漲價或封鎖 | 毛利與功能 | 多供應商 adapter（架構已有 gateway 層，落實 provider 抽象）；條款中保留調價權 |
| 一人營運（bus factor = 1） | 服務中斷無人處理 | 自動化告警 + 降級模式（已規劃）；文件化到「別人接得手」的程度（本倉庫的方向正確） |
| 公開倉庫洩露核心 | 被複製 | 核心移私有庫（見 4.2） |
| 帳號單點（GitHub/Cloudflare 個人帳號） | 全平台失守 | 全帳號硬體金鑰 2FA；公司化後轉組織帳號 |

## 8. 90 天路線圖

```text
第 1–2 週   基礎收尾
  □ 完成 OpenAI 網域驗證、修 mrliouhan.ai DNS（內網 IP、防偽記錄）
  □ 部署 status page、外部監控上線
  □ 四個正式信箱啟用
  □ main 分支 branch protection + CODEOWNERS 生效

第 3–6 週   可收費的最小 API 產品
  □ mrliouhan.ai 選定 1–2 個最有價值的 API 能力對外
  □ API 金鑰 + 用量計量落地（gateway 層）
  □ 定價頁 + 文件頁上線（mrliouword.com）
  □ TIPO 商標檢索與送件

第 7–12 週  正式營運
  □ 設立公司、會計師記帳、金流串接（MoR）
  □ 法律審閱後正式發布 ToS/Privacy/SLA
  □ 核心程式碼遷移私有倉庫
  □ 第一批付費使用者（目標 10 個）與回饋循環
```
