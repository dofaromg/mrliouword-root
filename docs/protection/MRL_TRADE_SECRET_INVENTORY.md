# MRL 營業祕密盤點（Trade Secret Inventory）v1.0 — WP-11

> 落實 [MRL World Model Engineering Plan](https://app.notion.com/p/3c38eeeec5b581be907ad10f49a51f1a)
> WP-11 之 Trade Secret 部分。營業祕密與著作權不同:**必須採取合理保密措施才成立**,
> 一旦公開即喪失祕密性,無法回復。

## 1. 成立要件（台灣營業祕密法第 2 條）

一項資訊要當營業祕密主張,須同時滿足:
1. **祕密性**:非一般涉及該類資訊者所知。
2. **經濟價值**:因其祕密而具實際或潛在價值。
3. **合理保密措施**:權利人已採取合理步驟維持其祕密。

> 第 3 點最常敗訴。**公開發布 = 自動喪失**。

## 2. 分類:哪些還能當祕密，哪些已公開

| 資產 | 目前狀態 | 可否主張營業祕密 |
|------|----------|------------------|
| MRL_MOTHER 未公開原始碼、內部演算法細節 | 僅本機 / 私有 | ✅ 可(若維持保密) |
| collapse engine / particle 內部實作細節 | 部分僅本機 | ✅ 可(未公開部分) |
| 客戶名單、定價策略、內部路線圖 | 未公開 | ✅ 可 |
| 憑證 / API key / 帳號 ID | **曾公開於證據頁** | ❌ 已洩,只能輪替止血 |
| 已公開發布的架構描述（如公開證據頁所載 particle 層級、workers 映射、bridge 設計） | **已公開** | ❌ 公開部分喪失祕密性 |

> **重要**:先前那份公開證據頁揭露了大量架構與憑證。**凡已公開的部分,不能再主張為營業祕密**——
> 但仍受**著作權**保護(著作權不因公開而喪失)。兩種權利要分開主張。

## 3. 合理保密措施清單（要主張祕密就必須做到）

- [ ] 標示:內部祕密文件加註「機密 / MRL Confidential」
- [ ] 存取控制:最小權限、憑證集中管理(見 MRL_SECURITY_BASELINE)
- [ ] 私有化:商業核心程式碼移**私有** repo,公開 repo 只留治理與文件門面
- [ ] NDA:未來有協作者 / 承包商時簽保密協議
- [ ] 稽核:記錄誰能存取祕密資產
- [ ] 分離:不在公開頁面、對話、commit 揭露祕密內容

## 4. 立即建議

1. **決定邊界**:哪些是「對外展示的原創(靠著作權 + 商標)」、哪些是「絕不公開的核心(靠營業祕密)」。兩者策略相反。
2. **核心私有化**:把仍具祕密性的核心(引擎、計費、母體邏輯)搬進私有 repo,別再放進任何公開位置。
3. **已公開者轉向**:對已公開的架構,改以**著作權**與**商標**主張,不再當營業祕密。
